## Правила из гайда по использованию ДС

1. **Главное правило.** Нет нужного варианта в свойствах компонента: не добавляй сам, сообщи команде ДС. Это повод доработать компонент.
2. **Приёмная ДС** (канал команды дизайн-системы): вопросы «как работает компонент», «а так можно?», не хватает функционала, предложения по улучшению.
3. **Не детачь компоненты.** Детач отрывает от мастера, обновления ДС не приходят. Детачить можно в процессе концепта, но **на ревью всё должно быть на компонентах**.
4. **Не переопределяй стили вручную:** шрифты, скругления, размеры, цвета. Чего нет в компоненте, того нет и в коде.
5. **Меняй вид только через свойства (props).**
6. **Не удаляй и не скрывай слои внутри дочернего компонента.** Скрытие делается через свойства.
7. **Не трогай gap, padding, corner radius:** они заданы системой.
8. **Не имитируй состояния** (hover, pressed, disable, active): они есть в свойствах.
9. **Добавляй компоненты через Assets** из актуальных библиотек. Нет библиотеки в файле: её нужно подключить.
10. **Проверяй актуальность** и отсутствие старых токенов. Устаревшие помечены специальными символами, найти их можно плагином Emoji Search.
11. **Анимация:** значения брать из таблицы в гайде (токены, которые использует разработка). Таблица в гайде лежит картинкой, текстом её не получить: сверяй вручную с гайдом.
12. **Темизация:** тема задаётся на уровне файла, и макет сам показывает нужные цвета продукта.

## Spacing (гайд Spacing)

Отступы в общем контейнере страницы задаются **только токенами группы `spacing`** (библиотека 🍏 Pole Mobile 2.0, коллекция `spacing`), а не примитивами. Точные имена переменных:

| Токен | Описание в Figma | Где ставить |
|---|---|---|
| `page/margin` | «отступ между секциями» | Зазор (gap) между секциями в контейнере страницы |
| `page/padding` | «Отступ от секции сверху и снизу» | Padding сверху и снизу контентной области страницы |
| `box/padding` | без описания | Вертикальный padding врезки между секциями без фона |
| `box/padding-horizontal` | без описания | Горизонтальный padding такой врезки |

Значения на примерах гайда:

| Что | Значение |
|---|---|
| Верхний и нижний отступ контентной области страницы (`page/padding`) | 4 |
| Отступ между секциями (`page/margin`) | 4 |
| Внутренний отступ контента секции с фоном (Section Primary) | 16 со всех сторон |
| Врезка без фона (Section Ghost): вертикальный `box/padding` | 12 |
| Врезка без фона: `box/padding-horizontal` | 16 |

Примитивы в переменных: `xs`=4, `s`=8, `m`=12, `l`=16. **Совпадение значения не делает примитив правильным токеном:** зазор между секциями 4, привязанный к `xs`, это находка, нужно `page/margin`. То же для верхнего и нижнего padding страницы: нужен `page/padding`, а не `xs`. Причина: при смене системных отступов макет с примитивами не обновится.

Какие токены стоят за `page/*` и `box/*` по значениям, в описаниях не сказано: значения в таблице выше взяты из примеров гайда. В `get_variable_defs` эталонного листинга видны только `s`, `m`, `l`, поэтому по эталону правильные токены не выбирай: опирайся на этот список и на гайд Spacing.

Что остаётся примитивами: внутренний padding контента секции с фоном (`l`), gap между блоками внутри секции (`m`), gap внутри ячеек (`s`). Для этих мест в гайде отдельных токенов нет. Если сомневаешься, пиши в «Нужно уточнить».

## Скругления

Шкала кратна 4px. Чем меньше элемент в иерархии, тем меньше скругление. Самый мелкий элемент внутри карточки (бейдж, аватар) скругляется полностью.

| Уровень | Радиус | Токен (по имени в эталонах) |
|---|---|---|
| 1. Секция | 28 | `сontainer/section`, `corner/28` |
| 2. Блок (контейнер с контентом) | 20 | `corner/20` |
| 3. Карточка и плитка | 12 | `сontainer/card` |
| Средние невысокие компоненты | 12 | — |
| Мелкие невысокие компоненты | 8 | — |
| Лейбл/аватар внутри карточки, полное скругление | `#round` | токен `#round` (иначе на iOS скругления выглядят криво) |

Радиусы, которыми владеет сам компонент ДС, снаружи не проверяются и не меняются: `button/radius/*` (12), `field/radius/*` (12), `chips/radius/small` (16).

В имени `сontainer/…` первая буква **кириллическая «с»**. Сопоставляй имена токенов терпимо к этому.

## Тени

Назначение: эффект возвышения одного элемента над другим. Выбор зависит от размера элемента.

| Тень | Когда |
|---|---|
| S | Слабая, с лёгкой обводкой. Небольшие объекты; состояние Pressed у большой карточки или компонента |
| M | Средняя слабая. Небольшие компоненты, например кнопки |
| ML | Средняя. Surface-карточки средних размеров |
| L | Большая. Surface-карточки крупных размеров; всплывающие элементы: pop-ups, toast, snackbars, tooltips; элементы на карте |
| XL | Очень большая. Модалки и окна предупреждений на всю страницу, большие объекты |
| Bottom panel | Обратная тень для нижних панелей: закреплённый контент с кнопкой внизу экрана, неблокирующие bottom sheet на карте |

Цветные тени (Colored shadow) относятся к старым логотипам продуктов, помеченным `🔴[old]`: на новых макетах не использовать. Токены цвета тени и стили эффектов в эталонах: `🍏 shadow/mono/l`, `🍏 shadow/mono/xl`, эффекты `🍏 L` (0, 4, blur 16) и `🍏 XL` (0, 6, blur 20).

## Маркеры в именах (как читать)

| Маркер | Что значит | Уверенность |
|---|---|---|
| `🍏` | Токены и компоненты текущей библиотеки ДС (Pole) | Высокая: подтверждено чек-листом |
| `🔴`, `🟥`, `[old]`, `(old)` | Устаревшее. Искать плагином Emoji Search | Высокая: подтверждено гайдом и именами в файлах |
| `🍋` | Компоненты продуктовых команд (Cart Layouts, Card cell «Команда Каталога») | Выведено из имён и описаний: не ДС-ядро. Уточнить у владельца, прежде чем судить |
| `.🔶` и имена с точкой | Внутренние служебные блоки компонентов | Выведено из имён |
| `🔥` | Встречается в описаниях («Компонент ДС», «Системный компонент») и у части токенов/компонентов | Неясно. Не флагать как устаревшее, выносить в «уточнить» |

## Как читать Figma через MCP (проверено на практике)

- **Детач.** В `get_metadata` у инстанса `type=instance`. В `get_design_context` слои внутри инстанса имеют id вида `I<id инстанса>;<id слоя>`, у детачнутой копии собственные id. Признак: фрейм с именем компонента, когда его соседи в том же списке инстансы, и внутри ручная сборка (например, слой картинки из двух растров с ручными смещениями вместо одного `object-cover`).
- **Привязка токенов.** В авторских фреймах привязанные значения выглядят как `gap-[var(--s,8px)]`, `rounded-[var(--сontainer\/card,12px)]`, а непривязанные как `gap-[8px]`, `rounded-[12px]`, `bg-[#f5f5f4]`. `get_variable_defs` на корне показывает, что реально привязано.
- **Внутренности компонентов** (`rounded-[16px]` у Row card, `rounded-[4px]` у Slider и т.п.) принадлежат библиотеке. Не считать их отвязанными токенами.
- **Кастомизацию инстанса** по голому коду надёжно не отличить: сравнивай с тем же компонентом в эталоне или в другом месте макета, смотри скрытые вложенные слои (`hidden="true"` внутри инстанса) и необычные размеры.
- **Скрытые узлы** в `get_metadata` видны как `hidden="true"`.
- `search_design_system` возвращает компоненты из всех библиотек: для замены бери результат только из нужной библиотеки и только когда роль ноды ясна.
- Описания компонентов в Figma (блок «Component descriptions» в ответе) содержат правила использования: читай их для найденных компонентов.

## Известные пробелы

- Пункт «Файл обновлён» полностью через MCP не проверяется: помечай «не проверено», если нет подтверждения.
- Таблица значений анимации лежит в гайде картинкой.
- Подробный текст пунктов DoD не вытягивался.
- Значение маркера `🍋` и статус `🔥` выведены или неясны (см. таблицу маркеров).
