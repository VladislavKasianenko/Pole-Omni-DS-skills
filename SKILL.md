# DS Review — ревью макета по дизайн-системе Pole Mobile 2.0

Проверяешь макет мобильного приложения Магнит по **✅ Checklist DS** и паттернам Magnit app 2.0.
Результат — пометки (аннотации Figma) на слоях с ошибками и короткая сводка в чате.
Каждая пометка: **что не так → как исправить → ссылка на гайд**.

## Что нужно

- Подключённый Figma MCP: `use_figma`, `get_screenshot`.
- Права на редактирование файла, чтобы поставить пометки. Нет прав — отдай сводку в чате и скажи, что пометки поставить не получилось.
- Перед первым `use_figma` загрузи инструкцию Figma `figma-use` (скилл `/figma-use` или ресурс `skill://figma/figma-use/SKILL.md`). Этого требует Figma MCP. В каждом вызове `use_figma` передавай `skillNames: "figma-use"` (или `"resource:figma-use"`, если загружал ресурсом).

## Порядок работы

### 1. Разбери ссылку

- `figma.com/design/<fileKey>/<имя>?node-id=12-34` → `fileKey`, `nodeId = "12:34"`.
- Ветка `figma.com/design/<fileKey>/branch/<branchKey>/<имя>` → вместо `fileKey` используй `branchKey`.
- Ссылка без `node-id` или на страницу целиком → попроси ссылку на **экран (фрейм)** или **секцию с флоу**. Страницу целиком не проверяй: там черновики и песочницы.
- FigJam, Slides, Make → ревью работает только с Design-файлами.

### 2. Автоматическая проверка — `scripts/audit.js`

Прочитай файл, подставь `ROOT_ID = '<nodeId>'` и отправь текст целиком в `use_figma` как `code`. Скрипт только читает файл.

Результат: `screens`, `totals`, `byRule`, `skipped`, `groups`. Каждая группа — одна будущая пометка:
`{ ids, n, scr, r, s, m, fx, g, more?, similar? }` — слой для пометки, сколько всего мест, экран, правило, критичность (`E` — ошибка, `P` — паттерн, `W` — проверить), что не так, как исправить, ключ гайда.
- Один и тот же элемент с одной проблемой (инстансы одного компонента, копии слоя на разных экранах) — **одна группа на весь флоу**: пометка на первом месте, остальные места в `more: [{ scr, name, id, n }]` по экранам. Пометка подскажет, где ещё поправить, со ссылками на слои.
- `similar` — сколько ещё мест с той же проблемой у других элементов на этом экране осталось без отдельной пометки (больше 5 разных элементов).
- `totals.groups` — сколько будет пометок, `totals.errors / patterns / checks` — сколько мест всего.
`skipped` — что не помечалось: `platform` — компоненты 🍋 команды Платформы, `system` — Status bar, клавиатура и т. п., `product` — копии компонентов продуктовых команд, собранных из 🍏 (всё в порядке).

- Пришёл `error` — перескажи его и остановись.
- `truncatedScreens: true` — проверены первые 40 экранов. Предложи прислать флоу частями.
- Находки `E` — факты о слоях, не переписывай их. Если на скриншоте видно, что находка ложная (например, hex внутри сложной картинки), выкинь её из пометок и упомяни в сводке.
- `product-component` — компонент продуктовой команды собран не только из 🍏. Сам компонент разрешён, в `m` перечислено, что внутри не так. Части «самодельный лейбл / кнопка / строка списка» — догадки по структуре: проверь по скриншоту и убери из `m` неподтверждённые (если не осталось ничего — выкинь находку). Остальные части — факты.
- Находки `P` и `W` от скрипта — кандидаты. Подтверди их на шаге 3 по скриншоту. Особенно `illustration-meaning` («красный крест»): реши по смыслу экрана, как описано в `references/patterns.md` → «Подбор иллюстрации по смыслу».
- Что означает каждое правило — `references/checklist.md`.

### 3. Проверка паттернов — скриншоты + `scripts/outline.js`

1. Запусти `scripts/outline.js` с тем же `ROOT_ID`. Если экранов больше 8, повторяй с `OFFSET = next`. Получишь структуру экранов с id слоёв.
2. Для каждого экрана — `get_screenshot` (`maxDimension: 1600`).
3. Сверь с `references/patterns.md`. Отмечай только то, что видно однозначно. Не дублируй находки `audit.js` (токены, hex, компоненты, детач, кнопки, шторки).
   Обязательно посмотри: компоненты продуктовых команд (лейблы, списки, кнопки внутри — из 🍏?), порядок кнопок, Primary для второстепенных действий, шторки и списки (🍏 Bottomsheet, 🍏 List), смысл иллюстраций (`illu=` в outline), табы, заголовки, тени на карточках.
4. Каждую находку оформи пунктом:
   `{ ids: ['<id слоя из outline или id экрана>'], n: 1, scr: '<id экрана>', s: 'P', r: 'pattern', m: 'Что не так', fx: 'Как исправить', g: '<ключ гайда>' }`.
   Не больше 5 пометок паттернов на экран — только самые важные.
   Та же проблема у того же элемента на нескольких экранах — **один пункт**, не по пункту на экран: `ids` — первое место, `n` — сколько мест всего, остальные места — в `more: [{ scr: '<id экрана>', name: '<имя экрана>', id: '<id слоя>', n: 1 }]`.

### 4. Сводка в чат

Коротко, по пунктам чек-листа (порядок как в `references/checklist.md`):

```
DS Review · <название секции или экрана> · экранов: N
❌ Файл обновлен — токены из старой версии библиотеки (3)
❌ Токены и компоненты из либы с 🍏 — 14 ошибок: устаревшие компоненты 2, hex 9, устаревшие токены 3
✅ Токены отступов Spacing
❌ Токены скруглений Container — 5
⚠️ Компоненты не закастомлены — 1 ошибка, 2 «проверить»
✅ Компоненты не раздетачены
🔵 Паттерны — 4 замечания: Primary «Назад», шторка собрана вручную, красный крест вместо Warning
Не проверялись: компоненты 🍋 Платформы — 12, системные элементы — 8
Компоненты команд, собранные из 🍏: 9 копий
```

- «Файл обновлен» напрямую не проверить. Если нет находки `outdated-library`, напиши: «проверь вручную: Assets → Updates — всё принято».
- Есть старые стили или токены (`deprecated-style`, `deprecated-token`, `web-token`) — подскажи, что все их быстро найдёт плагин ДС из закрепа DoD ДС.
- Повторяющиеся находки сводятся в одну строку с числом: «Card» не из ДС — 6 мест на 2 экранах, 1 пометка.
- Если пометки ставить не будешь — дай ссылки на слои: `https://www.figma.com/design/<fileKey>/?node-id=<id с «-» вместо «:»>`.

### 5. Пометки в макете — `scripts/annotate.js`

- `ITEMS` = все `groups` из `audit.js` (как есть, со всеми полями, включая `more` и `similar`) + пункты паттернов, без ложных. Не разворачивай `more` в отдельные пункты: одна пометка на элемент — так макет не тонет в пометках.
- Подставь `ROOT_ID`, `MODE = 'write'`, `ITEMS` и отправь в `use_figma`.
- `write` сначала убирает старые пометки DS Review внутри `ROOT_ID`, затем ставит новые. Чужие аннотации (логика, контент, разработка) не трогаются.
- Код в `use_figma` ограничен 50 000 символами. Если пунктов больше 60, дели на порции: первая — `MODE = 'write'`, остальные — `MODE = 'append'`.
- Порядок важности: `E` → `P` → `W`.
- Ставь пометки, если человек просил ревью. Если просил «только посмотри» или «без пометок» — остановись на шаге 4.

### 6. Финал

Одним-двумя предложениями: сколько пометок поставлено (и на сколько мест они указывают) и где их смотреть. Это аннотации на слоях, категория **DS Review**; в Dev Mode — панель аннотаций. Повторное ревью заменит старые пометки. Убрать — попросить «убери пометки DS Review».

## Режимы

- «Убери пометки DS Review» → `annotate.js`, `MODE = 'clear'`, `ITEMS = []`.
- «Только отчёт» → шаги 1–4.
- «Перепроверь» → весь цикл, старые пометки заменятся.
- Проверить план без записи → `MODE = 'dry'`.

## Правила ревью

- Источник правды — `references/`. Не придумывай правил. Сомневаешься — это «🟡 Проверить», а не ошибка.
- Не проверяем: тёмную тему (пока её нет), анимации, редактуру текстов, задачи исследователей, редакторов и Платформы, DoD других команд.
- Устаревшие компоненты — только с 🔥 / 🔴 или `[old]` (Pole Mobile 1.0). Компоненты с другими эмодзи (🍔, 🖼️ …) или без — компоненты продуктовых команд: не ошибка, проверяем их состав.
- Не проверяем и не помечаем компоненты 🍋 (платформенные компоненты команды Платформы), 🍏 Platform Components 2.0 (Status bar, Home indicator, Keyboard) и служебные элементы флоу `[Tools]`.
- Пометки — только внутри присланного экрана или секции.
- Тон: коротко, на «ты», без оценок дизайнера. Формулировки — как в гайдах ДС.
