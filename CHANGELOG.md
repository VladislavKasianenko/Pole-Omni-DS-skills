# Changelog

## 0.8.0 — 2026-10-28

Тест на трёх моделях (Haiku, Sonnet, Opus 5.5) на одних и тех же экранах. Только Opus запустил скрипты навыка и сам поставил пометки. Haiku и Sonnet написали свой код и свои тексты пометок (без формата DS Review), а пометки поставили только после отдельной просьбы. Отсюда разные и лишние находки: скрытый Header в компоненте команды, имена слоёв, «проверь, откуда компонент».

- Проверка и пометки — один вызов: `scripts/review.js`. Модели больше не нужно переносить находки из одного скрипта в другой, а пометки ставятся сразу, без вопроса.
- Скрипты навыка собираются из читаемых исходников `src/` в сжатом виде (`tools/build.mjs`): review.js — около 35 000 символов вместо 44 000 + 13 000.
- SKILL.md: главные правила в начале — только скрипты навыка и только целиком, без своего кода и ручных аннотаций, без вопроса перед пометками. Не удаётся передать скрипт — остановиться и сказать об этом.
- В сводке строка «Проверено: ds-review X.Y.Z» — видно, что работал скрипт навыка и какой версии.
- Строка из фреймов с текстом и шевроном (например, адрес «Санкт-Петербург ›») — `ds-lookalike`: замени на 🍏 List. Работает на экранах, а не только внутри компонентов команд.
- Шаг 3 (паттерны по скриншоту): не отмечать скрытые слои в компонентах команд, положение слоёв, «проверь, откуда компонент». «Красный крест» помечает скрипт, ИИ его не дублирует.
- Автотест собранного review.js (`tests/mock-review.mjs`): report не меняет файл, write ставит пометки в формате DS Review, повторный write заменяет их.

## 0.7.0 — 2026-10-28

Одинаковый результат на разных моделях. Проверка: одни и те же экраны («VK — Hard Work» и «[2.0] RTE»), Sonnet 5.5 и Opus 5.5. Автоматическая часть совпала, расходились только пометки по скриншоту: Sonnet поставил 5, Opus — 0.

- Заливка и отступы секций теперь проверяются скриптом, а не на глаз: `section-fill` (секция на `🍏 global/background/…` вместо `🍏 surface/primary`) и `section-padding` (внутри секции 16 со всех сторон, между заголовком и контентом 12).
- Проверка по скриншоту стала закрытым списком. Пометка ставится, только если правило записано в паттернах или чек-листе, нарушение однозначно видно и его нет в находках скрипта. Не отмечаются продуктовые решения, настройки Figma (Clip content), советы «проверь, есть ли» и сравнения без правила.

## 0.6.0 — 2026-10-28

Калибровка по файлу «VK — Hard Work», страница «на ревью» (эталон почти без ошибок): было много ложных пометок, осталась одна настоящая.

- Устаревшие компоненты — только 🔥 / 🔴 / 🟥 или `[old]` в названии (Pole Mobile 1.0). Компоненты с другими эмодзи (🍔 Restaurant Card, 🖼️ Image_S) — компоненты продуктовых команд: проверяется их состав.
- Раздетаченным компонентом считается только фрейм с 🍏 или устаревшим эмодзи.
- Цвет иконки внутри 🍏 компонента на 🍏 токене после замены иконки через свойство — не кастомизация (🍏 Tabs Segmented).
- Сравнение переопределения с мастером работает и для мастеров из библиотек (по пути слоя).
- Самодельный список — только если в столбике минимум 2 строки с шевроном или контролом. Одиночная строка в карточке (Promocode card) — не список.
- Шапка из склеенных блоков (gap 0, скруглён только низ) — не контейнер с секциями.
- Градиентное затемнение поверх фото — часть картинки, не ошибка цвета.
- Исправлено: внутри компонентов команд не отбрасывался hex в сложных картинках и не сворачивались самодельные иконки.
- Пояснения к коду `audit.js` перенесены в `docs/how-audit-works.md`: скрипт ужат с 47 900 до 42 800 символов (лимит `use_figma` — 50 000).

## 0.5.0 — 2026-10-21

- Пометка читается проще: после «🔴 Ошибка» нет названия пункта чек-листа, блоки разделены пустой строкой, «Что не так» и «Как исправить» — списками.
- Переопределение, значение которого совпадает с мастером (выключили и включили тень, поменяли цвет и вернули), больше не считается кастомизацией.

## 0.4.0 — 2026-10-20

Компоненты продуктовых команд.

- Свой компонент команды (без эмодзи, локальный или из библиотеки команды) больше не помечается сам по себе. Вместо этого навык проверяет, из чего он собран (`product-component`): вложенные компоненты, токены, стили, иконки, самодельные элементы.
- Самодельные лейблы и чипы, кнопки и строки списка внутри компонента команды (`ds-lookalike`) — догадка по структуре, ИИ подтверждает по скриншоту.
- Содержимое проверяется один раз на мастер-компонент, пометка — одна на все копии, со ссылкой на мастер-компонент, если он в этом же файле.
- Кнопки внутри компонентов команды не считаются Primary экрана (`multi-primary`).
- Правила `non-ds` и `local-component` заменены на `product-component`.
- `tools/check.sh`: лимит размера отдельно для каждого скрипта (`annotate.js` дополняется пунктами).

## 0.3.0 — 2026-10-20

Меньше пометок на макете.

- Одна и та же проблема у одного элемента — одна пометка на весь флоу, а не на каждую копию. Элемент — это инстансы одного компонента или копии слоя (то же имя и ширина) на разных экранах.
- В пометке строка «Этот же элемент ещё в N местах — поправь и их» со списком экранов и ссылками на слои.
- Больше 5 разных элементов с одной проблемой на экране — остальные считаются в той же пометке («Та же проблема ещё в N местах у других элементов»).
- Пункты паттернов от ИИ тоже собираются в один пункт на элемент (`more`).
- Автотест: флоу из двух экранов, локальный компонент в 6 местах → одна пометка.

## 0.2.0 — 2026-10-20

Калибровка по ручному ревью «[2.0] Косметик».

- Компоненты 🍋 — платформенные компоненты команды Платформы: не проверяем и не помечаем (раньше были «Проверить»).
- Hex на иконках — ошибка `icon-hex`: переопределение цвета иконки, вектор до 48 px с hex, иконка, собранная вручную (одна пометка на иконку).
- Раздетаченные иконки и иллюстрации (фрейм с именем `Base / 40 / …`) — `detached`.
- Шторка, собранная вручную из 🍏 Bottomsheet Header и фреймов, — `manual-bottomsheet`.
- Паттерны кнопок: порядок по важности сверху вниз (`button-order`), Primary для «Назад» и «Отмена» (`secondary-primary`), несколько Primary на экране (`multi-primary`). Inline button не считается.
- «Красный крест» (иллюстрация Error / Failed) — `illustration-meaning`: ИИ решает по смыслу экрана, нужна ли замена на Warning.
- Пометки про старые стили подсказывают плагин ДС из закрепа DoD ДС.
- `outline.js` показывает иллюстрации внутри компонентов.
- `tools/check.sh` проверяет, что скрипты укладываются в лимит `use_figma`.
